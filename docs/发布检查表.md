## C. 已知风险与回退

| 风险 | 影响 | 回退方式 |
|---|---|---|
| 真实抓取未开（`COLLECTOR_MODE=fixture`） | 目前不产生外部请求；生产要改配置 | 改回 `fixture` 即恢复零外部请求 |
| `LLM_MODE=off` | 归因为规则版，粒度粗 | 填 Key + `LLM_MODE=openai` 即启用；失败自动降级 |
| 迁移顺序敏感（`shared.0002` 搬 schema） | 新增 shared 表必须同步登记，否则建到 `app` | 已写入迁移注释；发布前 `showmigrations` 核对 |
| 长任务租约 | 若 handler 超出租约（日报 60 分钟）会被回收 | 调大 `LEASE_SECONDS` 或让 handler 续租 |
| 无远端仓库 | 无法异地备份/协作；`git ls-remote` 不可用 | 接入 GitHub/GitLab 后 `git remote add` + push，并校验远端 tag |
| 效果回看依赖「7 天后仍有采集」 | 目标被删/长期熔断时回看为 `unavailable` | 报表会把它单列，不计入效果判断 |

## D. 发布步骤

```bash
# 1. 备份（失败即中止）
PG_CONTAINER=pg-competitor bash scripts/backup.sh

# 2. 全量门禁
ruff check . && pytest -q && python scripts/verify_pg_rls.py

# 3. 迁移 + 重启
docker compose up -d --build        # init 服务会先跑 migrate

# 4. 冒烟
curl -fsS http://127.0.0.1:8000/health

# 5. 打 tag（仓库初始化后）
git add -A && git commit -m "release: v0.2.0"
git tag -a v0.2.0 -m "v0.2.0"
git push origin main --tags
git ls-remote --tags origin | grep v0.2.0   # 用远端 refs 校验，不信 push 退出码
```
