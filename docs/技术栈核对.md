# 技术栈核对（对照 market-tech-stack-atlas）

- 日期：2026-10-22
- 对照基准：图鉴 12 层分类 + `playbooks.md` 的 **P4 多租户 B2B SaaS**（本项目形态最接近）与 **P9 政企私有化**
- 结论：**核心四项与图鉴默认完全一致，三项有意偏离（都有成本理由），三项是真缺口**

## 一、逐技术位对照

| 技术位 | 本项目 | 图鉴默认（P4） | 判定 |
|---|---|---|---|
| 服务形态 | Django 模块化单体，`web` + `worker` 两进程 | ★ 模块化单体 + 清晰租户上下文 | ✅ 一致 |
| 后端框架 | Python 3.12 + Django 5.2 | 04 层 Django = 「内容型业务与后台管理」默认 | ✅ 一致 |
| 前端 | Django 模板 + HTMX（本地 vendor） | ★ React + Ant Design Pro | ⚠️ 有意偏离（见 §2） |
| 数据 | PostgreSQL + 共享库 + `tenant_id` + **RLS** | ★ PG 共享库 + 行级隔离 + RLS | ✅ 完全一致（含 atlas 那句「把 tenant_id 当可选过滤条件就是越权事故」） |
| 租户上下文 | 中间件 + contextvar + `SET LOCAL`（事务级） | 「租户 ID 必须能从网关贯穿到 SQL」 | ✅ 一致，且用 `SET LOCAL` 而非 `SET` |
| 异步 | PG 任务表 + `SKIP LOCKED` | ★ RabbitMQ / Redis Streams | ⚠️ 有意偏离（见 §2） |
| 限流/熔断 | 自研令牌桶（落库）+ 熔断状态机 | Sentinel（Java）/ 网关插件 | ⚠️ 偏离：Python 无对等品，自研需跨进程持久化 |
| 可观测 | structlog JSON + `metric_daily` + `/ops/health` + 每日自检邮件 | ★ Prometheus + Loki + Sentry + 按租户标签 | ⚠️ 偏离 + 缺口（见 §3） |
| 认证 | Django session + 登录节流（落库） | ★ Keycloak / 自建 OIDC + 企业 SSO | ❌ 真缺口 |
| 权限 | 四档 role（admin/operator/designer/viewer）+ 数据权限在 SQL 层 | ★ Casbin RBAC + 数据权限在 SQL 层 | ⚠️ 数据权限已对齐；功能权限偏粗 |
| 计费/配额 | `quota_json`（目标数上限） | ★ 自建订阅/配额 + 支付网关 | ❌ 缺口（一期不需要） |
| 部署 | Docker Compose 单机（db/init/web/worker） | 单集群多命名空间 → 大客户独立 | ⚠️ 一期私有化合理 |
| 数据生命周期 | 400 天保留 + BRIN 索引（ADR-005） | 「规模化拐点：单库 5000 万行 → 分库」 | ✅ 方向一致，阈值写死 |

## 二、三项有意偏离（不是漏做，是算过账）

**1. HTMX 而不是 React**
图鉴 02 层对 HTMX 的定位是「服务端渲染为主的内部系统」，本项目 9 个页面里 7 个是「表格 + 表单 + 详情抽屉」，交互只有轮询与局部刷新。
ATAM 里「总代码量与组件数最小」是单人维护的硬约束：上 React 要多一条构建链、一套状态管理、一份 API 契约。**取舍点**：当出现「拖拽看板 / 复杂图表联动 / 移动端适配」需求时，再引入前端框架。

**2. PG 任务表而不是 RabbitMQ / Redis Streams**
图鉴组合三原则第 2 条就是「能少一个组件就少一个」。本项目日任务量在万级以内，需要的是「可查、可重放、可手工重试」，而不是高吞吐分发。
**取舍点**：需要多消费者组、消息重放、跨语言消费时换 Redis Streams（复用 PG 做持久化也可以，但那时应该换 MQ）。

**3. 自研限流而不是 Sentinel**
Sentinel 是 Java 生态；Python 侧 `limits`/`slowapi` 都是**进程内**计数，多 worker 直接失效。
本项目需要的是「跨进程共享 + 重启不丢预算」，最小实现就是把令牌桶存成一行数据库记录，40 行代码，比引入 Redis 更省。

## 三、三项真缺口（按优先级）

| 缺口 | 影响 | 建议路径 | 触发时机 |
|---|---|---|---|
| **企业 SSO（OIDC/SAML）** | B 端客户采购时几乎必问；目前只有账号密码 + 角色 | 引入 Keycloak 或直接对接客户 IdP；Django 侧用 `mozilla-django-oidc`。登录后仍落本地 session，租户映射保持不动 | 第一个要求 SSO 的客户前 |
| **错误追踪** | 现在异常只在 JSON 日志里，被动发现；私有化环境不能用 SaaS Sentry | 自托管 GlitchTip（Sentry 协议兼容、资源占用小）或加一个 `/health` 之外的异常聚合表 | 上线后第一次线上排障 |
| **按租户成本/用量视图** | `metric_daily` 的 LLM token 是全局口径，做了 SaaS 之后无法按租户计费或限流 | 新增 `llm_usage(tenant_id, day, tokens_in, tokens_out, cost)`，写入点已在 `infra/llm/client.py` | 从单租户走向多租户售卖时 |

## 四、规模化拐点（到了就换，不提前做）

| 信号 | 动作 |
|---|---|
| 监控目标 > 5,000 或时延 P95 > 90s | worker 横向扩到多进程（调度仍单实例），PG 队列加分区索引 |
| `shared.snapshot` > 2,000 万行 / 50 GB | 按月分区（ADR-005 预案：双写 → 回填 → 切读 → 删旧） |
| 单库连接数 > 80 | 上 PgBouncer（`pool_mode=transaction`），注意 `SET LOCAL` 语义仍然成立 |
| 客户要求信创 | **KingbaseES 可平迁**（PG 兼容，含 RLS）；达梦 DM8 需逐条验证 RLS 与类型语义，工作量按 20% 工期预留 |
| 出现「导出/报表拖慢主库」 | 只读副本 + 把导出改异步任务（当前导出已同步返回，行数上限 200） |

## 五、取舍说明一句话版

没选 React：页面形态不需要，单人维护成本翻倍。
没选 Redis/Celery：任务量不到，且「任务就是一张表」在排障时更值钱。
没选 Sentry SaaS：私有化交付不能依赖外部服务。
没选达梦：当前没有信创客户，PG 的 RLS 是本项目隔离红线的基础。
