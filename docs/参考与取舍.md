# 参考与取舍：GitHub 同类项目给了什么，我们拿了什么

先给结论：**没有抄代码，只借鉴了行为**。这类项目解决的是「监控任意网页变没变」，
我们解决的是「单类目竞品的到手价变了多少、我方该不该跟」。定位不同，功能照搬就是负债。

主要参考对象：[changedetection.io](https://github.com/dgtlmoon/changedetection.io)
（Apache-2.0，Python，~32k stars，Docker 单容器，支持 CSS/XPath/JSONPath 选择器、
restock/price 模式、通过 Apprise 接 85+ 通知渠道、可选 Playwright 渲染 JS 页面）。
另外参考的是 Scrapy 生态与多家抓取服务商公开的工程实践文章（条件请求、Retry-After、
规范化去重），这些是行业共识而非某个具体项目的能力。

## 一、采纳了什么（3 条，都是 HTTP 标准）

| 借鉴点 | 落地 | 为什么值得 | 验证 |
|---|---|---|---|
| **条件请求**（`If-None-Match` / `If-Modified-Since` → 304） | `Target.http_etag / http_last_modified`，304 时**不落快照**、只推进 `next_due_at` | 页面没变时几乎不花站点资源、不花我们带宽预算。这是「最省预算的礼貌」，比任何降频技巧都有效；同时减少请求体量也就减少风控暴露面 | `tests/unit/test_conditional_fetch.py`、`test_not_modified_skips_snapshot` |
| **尊重 `Retry-After`** | 429/503 时熔断冷却取 `max(默认冷却, Retry-After)`，上限 24h | 站点明确说了「多久之后再来」，按它等比自己拍一个固定值更准也更礼貌；避免解封后又立刻撞墙 | `test_retry_after_extends_circuit_cooldown` |
| **尊重 `Crawl-delay`** | robots 解析新增 `Crawl-delay`，采集间隔取 `max(配置间隔, crawl-delay)` | 站点用 robots 明确表达频率下限；这是合规评审最容易问到的一条 | `test_robots_crawl_delay_is_parsed_and_can_stretch_interval` |

顺带确认了两个我们本来就在做、而且做法一致的：

- **只关心若干字段，而不是整页**：changedetection 用选择器圈元素，我们用字段级 diff（`changed_fields`）
- **内容哈希去重**：我们用 `fingerprint()` + `sha256(body)`，避免「同一内容重复落库」

## 二、明确不采纳（6 条，附理由）

| 不采纳 | 他们的做法 | 我们为什么不做 |
|---|---|---|
| Playwright / 无头浏览器渲染 | 可选 `sockpuppetbrowser` 容器渲染 JS 页面 | 单页 3~8 秒、成本高、**更易被识别为自动化**，与我们「低频、只读、固定 IP」的合规定位直接冲突。真需要渲染时，说明这个数据源本身不该碰 |
| 85+ 通知渠道（Apprise） | 一个依赖接所有 IM | 单人维护不起；每多一个渠道就多一类「半夜通知不到」的可能。我们只做 企微 → 邮件 → 站内 三级降级，够用且每级都能查 |
| 视觉 / 截图 diff | 像素级对比 + 截图附在通知里 | 价格页有轮播、推荐位、时间戳，视觉 diff 误报极高；运营要的是「降了多少、要卖多少件打平」，不是像素差 |
| 可视化选择器（点选元素） | 需要浏览器 + 交互式选取 | 我们用「6 个强结构标记 + 字段正则」，改配置即可热修（≤4h 修复目标），不需要跑浏览器 |
| 通用「任意 URL 监控」定位 | 任意站点、任意内容 | 通用化会稀释核心价值：到手价求解、毛利与打平测算、8 字段可执行卡片。我们宁可窄 |
| LLM 自然语言变更规则 | 「价格低于 50 欧才通知」交给模型判断 | 我们的结论必须可复现、可通过「抽检一致率 ≥99%」验收；再套一层 LLM 判断会让同一输入两次结果不同，验收直接失效 |

## 三、反过来，我们做了他们没有的

这些是「单类目 + 商家视角」带来的差异，不是能力强弱：

1. **到手价求解**：券/满减/每满减/秒杀叠加，算不出标 `uncertain`（他们只比价格数字）
2. **毛利与打平销量**：跟价后毛利率、需要多少倍销量打平、是否跌破底线
3. **8 字段可执行卡片**：责任人、时限、验收标准，而不是一条「页面变了」的通知
4. **多租户隔离**：双 schema + RLS fail-closed + 越权 6 条 CI（他们是单用户工具）
5. **证据子串强制校验**：模型编造促销必须编造一段能在原文找到的引文，做不到就丢弃

## 四、如果以后要接更多省份/平台

留了三个口子，不需要改架构：

- `Target.platform` 字段（已留，当前 `taobao`）
- `Target.source`：`official_api | data_vendor | public_sample` —— 合规评审不过时切到官方/采购源
- `STRONG_MARKERS` 与 `LEXICON` 都是纯配置，换类目/站点只改这两个文件并补样本页
