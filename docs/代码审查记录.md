## 二、Major（14 修 / 1 转 ADR）

| # | 问题 | 处理 |
|---|---|---|
| M1 | `SET LOCAL` 在嵌套 savepoint 中**不会**随 savepoint 释放而回滚，`audit()` 的临时上下文会污染外层请求 | 已修：`tenant_atomic()` 记录旧值并在 `finally` 显式恢复 |
| M2 | 幂等键 check-then-create 有竞态，撞唯一约束会抛异常，导致重复采集/重复事件 | 已修：`enqueue` 用 savepoint + `IntegrityError` 兜底返回 `None` |
| M3 | worker 每轮 claim 多于线程数，任务被提前标 running 却没执行 → 租约到期被回收 → **同一任务并发跑两遍** | 已修：加 `_inflight` 计数背压，只 claim 空闲槽位 |
| M4 | 回收阈值固定 300s，日报这类长任务会被误判死亡 | 已修：`Job.lease_until` 按任务类型给租约（日报 60 分钟），回收按租约判断；新增 2 条用例 |
| M5 | worker 主线程连接从不回收，DB 重启后永久卡在 claim 失败 | 已修：主循环顶部 `close_old_connections()`，异常分支额外 `connection.close()` |
| M6 | 记账（缓存/指标/用量）写失败会连坐业务结果，与 docstring 相反 | 已修：三步各自 `try/except` 只告警 |
| M7 | 4xx 全部重试（401/403/400 重试只会放大故障），429 也没读 `Retry-After` | 已修：新增 `_FatalLlmError`，只有 5xx/429 重试 |
| M8 | `LLM_PROMPT_VERSION` 是死配置；改它会 `FileNotFoundError` 让分析任务全灭 | 已修：`load_prompts(get_settings().llm.prompt_version)`，文件缺失时降级到规则路径 |
| M9 | 成员表单未校验 `role`，租户管理员可 POST `role=platform_ops` 拿到平台视图（横向提权） | 已修：角色白名单，显式拒绝 `platform_ops`；新增 2 条用例 |
| M10 | `next.startswith("/")` 放过 `//evil.com` → 开放重定向 | 已修：`url_has_allowed_host_and_scheme` |
| M11 | CSV 导出未处理公式前缀（`=`/`+`/`-`/`@`），Excel 会执行 | 已修：`_csv_safe()` 统一加单引号，水印行同样处理 |

## 三、Minor（22 修 / 9 书面接受）

已修（摘要有行为影响的）：

- 事件去抖落地：30 分钟内同类变化合并为同一事件（价格往复不再刷屏），并用「事件+快照」做分析幂等键，保证卡片会刷新
- 抓不到价时**清空** `last_price_*`，不再让工作台拿过期价格算竞争力
- `fail_streak` 改 `F()` 原子自增，避免并发把熔断状态覆盖回去
- 秒杀价补进 `promo_detail` 序列化（否则证据链里复算不出到手价）
- 0 元展示价按「缺失」处理，不再夹到 0.01
- 满减/每满减并存时，每满减也出现在明细里（标未参与计算）
- 非价格变化给字段权重（title 5% / promo 3%），core 租户的标题变化能进 P0
- `queue_stats` 删除永远为 0 的 `failed` 状态；`purge_finished` 默认改 30 天（避免过早释放幂等键）
- 日报收件人改为**仅平台运营**（正文含全平台聚合，不能发给每个租户管理员）
- `seed_demo` 在 `APP_ENV=prod` 下拒绝执行（避免固定口令后门账号）
- `is_staff` 恒 False（平台运营走 `/ops/health`，不进 Django admin）
- `AnalyticsEvent` 补作用域管理器（SQLite 下不再跨租户）
- `TRUSTED_PROXY` 开关：未配反向代理时不信 `X-Forwarded-For`
- `EMAIL_TIMEOUT=15`（防 SMTP 挂住永久占线程）
- 商品表单：非法小数不再 500；缺字段不再静默清空成本
- 配额显示改为全量计数（不再随筛选变小）；任务页 N+1 → `in_bulk`

书面接受（附理由）：

| 项 | 接受理由 |
|---|---|
| 预算令牌在幂等命中时不回补 | 最坏是「少采一次」，方向安全；回补逻辑会引入跨事务写 |
| `httpx` 每请求新建 Client | 纯性能损失（每请求一次 TLS 握手），无泄漏；单机 1 QPS 下可忽略 |
| robots 缓存无 TTL/上限 | 域名规模极小（单类目 + 固定商户），长期运行也不会增长到需要治理 |
| `max_bytes` 是先整包读入再截断 | 12s 超时 + 3MB 截断把最坏内存限制在几十 MB；改流式读取要重构 `FetchResult`，收益不等价 |
| 读请求也开事务（RLS 需要 `SET LOCAL`） | 改成「只有写请求开事务」会引出 `SET` 泄漏风险；见 ADR-006 §5 的触发条件 |
| `merge_jitter` 函数本身仍未被调用 | 行为已由 `handle_collect` 的 30 分钟去抖覆盖；函数保留供离线分析复用 |
| 字段名 `sekill_price` 拼写错误 | 全链路一致、且已序列化；改名会牵动 4 个文件与历史数据，收益仅为可读性 |

## 五、这轮审查的元结论

1. **测试全绿 ≠ 系统正确**：B3 的根因是「只在 SQLite 上验证过写路径」，而 SQLite 没有权限模型。
2. **「注册了 handler」不等于「会有人投递」**：B4 是最典型的「代码写了、接线忘了」，任何没有端到端断言的调度都该怀疑。
3. **降级路径本身也会崩**：B1 崩溃点就在「给不出的结论」那条分支上，越是兜底代码越要有测试。
