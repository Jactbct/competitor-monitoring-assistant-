# ADR-006：明确推迟的四项，以及各自的触发条件

- 日期：2026-10-22
- 状态：已接受
- 触发来源：独立代码审查（见 `docs/代码审查记录.md`）与《技术栈核对》的缺口清单

「不做的决定」也要留痕，否则半年后有人问「为什么没有 SSO」，答案是沉默，然后重写一遍。

---

## 1. 企业 SSO（OIDC / SAML）

**现状**：Django session + 邮箱密码 + 登录节流（失败 5 次锁 15 分钟，计数落库）。

**为什么现在不做**：手头没有客户 IdP 可联调；SSO 的坑几乎全在对方配置（entity id、断言签名、
组映射），写完不联调等于没写。

**触发条件**：第一个在采购流程里明确要求 SSO 的客户。

**实施路径（预估 2~3 天）**：
1. 用 `mozilla-django-oidc`，新增 `/oidc/callback`，登录成功后仍落本地 session；
2. 租户映射规则：`email` 域 → 租户，或 IdP 组属性 → 租户（二者都要支持，客户偏好不同）；
3. 本地密码登录保留为兜底（IdP 故障时运维还能进）；
4. 审计动作加 `auth.login_sso`，记录 `iss`/`sub`（不记录 token）。

## 2. 导出改异步

**现状**：`GET /suggestions/export.csv` 同步生成，上限 200 行，实测 12ms。

**为什么现在不做**：当前量级下同步更快也更简单；一旦改成「任务 + 轮询下载」，就多了一个状态机、
一个文件生命周期、一个下载鉴权，收益为零。

**触发条件**（任一）：
- 单次导出 > 5,000 行，或 P95 > 2s；
- 导出开始影响其他请求（DB CPU 抖动）；
- 客户要求「导出全部历史」。

**实施路径**：复用现有任务表，`kind=export`，产物写 `.data/exports/{uuid}.csv`（24 小时清理），
下载路由带一次性 token（HMAC 签名 + 过期时间），水印与审计逻辑不变。

## 3. 大客户物理隔离（独立库 / 独立实例）

**现状**：共享库 + `tenant_id` + RLS，所有租户一个库。

**为什么现在不做**：独立库会让「一次迁移服务 N 个租户」变成「N 次迁移」，单人维护直接崩。
Atlas 的 P4 剧本也明确建议「先共享库，把独立部署做成可选项」。

**触发条件**：客户合同要求物理隔离，或单租户数据 > 单库容量 30%。

**实施路径**：不改代码结构，只改部署单元 —— 同一套镜像起第二套 compose，`DATABASE_URL` 指向新库，
导入该租户数据；`Tenant` 表里加 `deployment='dedicated'` 标记，便于运营区分。这条路能走通的前提是
「所有查询都带租户过滤 + RLS 兜底」，这两条已经成立。

## 4. N1（促销抽取）接入生产链路

**现状**：`n1_extract_promos`（含证据子串校验）只在测试里被调用；生产链路直接走**规则引擎**抽促销，
N2 只做归因/影响/建议，靠「证据 ID 必须存在」这一道门。

**为什么现在不接**：接 N1 需要把「页面正文」存进快照（现在只存了促销句子），否则证据子串校验
必然全量失败；而存正文会让快照体积涨 10~50 倍，与 400 天保留直接冲突。这是个需要先做取舍的设计题，
不该在收尾阶段仓促接上。

**如实说明**：`docs/能力规格.md` 已按实际实现改写，不再宣称「三道门在生产全生效」。
当前生产实际生效的是两道：schema 校验 + 证据 ID 回链；规则引擎本身是确定性的，不需要证据校验。

**触发条件**：出现「规则引擎抽不出的促销形态」且发生频率 > 5%（用 `probe_page` 抽样统计）。

**实施路径**：快照只存「促销区正文摘要」（≤2KB，不进主表，放 `raw_object_key` 同级的独立小对象），
N1 拿摘要做证据校验，校验通过的条目才与规则结果合并。

## 5. 中间件事务范围（读请求也开事务）

**现状**：每个请求都 `transaction.atomic()` + `SET LOCAL app.tenant_id`（RLS 需要事务级变量）。

**为什么保留**：改成「只有写请求开事务」会让读请求失去 `SET LOCAL` 的容器，得改用 `SET` + 手动重置，
那正是本项目在 ADR-001/§8 里明确避开的泄漏风险。当前 4 个 gunicorn worker、单请求 10~60ms，
事务开销可以接受。

**触发条件**：出现「长事务拖住 autovacuum」或 P95 超过 200ms。
**届时方案**：读请求改用 `SET LOCAL` 包在一个显式的短事务里（`with atomic(): ...` 只包查询），
而不是去掉事务。
