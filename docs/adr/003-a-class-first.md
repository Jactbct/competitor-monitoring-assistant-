# ADR-003：一期主打 A 类（商品信息），B 类（跟价）默认不自动推送

- 日期：2026-10-21
- 状态：已接受
- 影响：`domain/analyze/decide.py`、`B_CLASS_ENABLED`、所有跟价类卡片

## 背景

架构文档 §7.2.1 指出：一期只有公开页采样，不采登录态 → 拿不到定向券、会员价、部分秒杀价；
而「不确定即标注、绝不估算」是硬约束。三者叠加，`price_confidence='uncertain'` 的比例可能超过 50%，
而 B 类（跟价）的**全部结论都建立在到手价之上**。

## 决策

1. `B_CLASS_ENABLED` 默认 `0`。价格类变化默认落 `price_notice` 卡：
   **给数字不给指令** —— 展示价/到手价变化、让利额、毛利率变化、打平销量倍数，全部算出来，
   但结论是「人工核算后决定是否跟价」，`quality_gate=manual_required`，不自动推送。
2. 打开闸门的条件：M1 末用 100 条真实链接实测到手价可确定率 **≥70%**。
3. B 类打开后仍需成本存在（`self_product.cost` 非空），否则退化为「请先补录成本」引导卡（EX-07）。
4. 无论哪类卡片，只要到手价 `uncertain`，措辞里不出现「到手价 = X」，改为「展示价对比」。

## 后果

- ✅ 一期不会因为「到手价算不准」而给出错误调价建议（那是真实亏损）
- ✅ 运营仍然第一时间知道「竞品降了 23%」，只是最后一步由人拍板
- ⚠️ 客户感知：信息类建议（改标题、补属性）的效果比跟价滞后，需要销售话术配合
- ⚠️ 需在对外材料中明确写「本期不含精确跟价」，不可含糊（P-7）

## 反对意见

「B 类才是核心卖点，默认关闭会显得产品弱。」
接受这个代价：宁可给可回滚的标题建议，不给基于不确定价格的调价建议。
M1 拿到实测数据后再打开，只是延后，不是放弃。
