# 常驻运行（Windows 计划任务）

目标：**不依赖任何终端窗口**，机器不关机就一直在跑；到点自动关机。

当前部署（2026-10-22 16:30 起）：

| 任务名 | 触发 | 动作 | 日志 |
|---|---|---|---|
| `CompetitorWeb` | 用户登录时 | `manage.py runserver 127.0.0.1:8000` | `.data/logs/web.log` |
| `CompetitorWorker` | 用户登录时 | `manage.py run_worker --concurrency 2` | `.data/logs/worker.log` |
| `CompetitorShutdown` | **2026-10-25 10:00**（一次性） | `shutdown /s /f /t 60` | 事件查看器 |

## 常用命令

```powershell
# 看状态
Get-ScheduledTask -TaskName "Competitor*" | Select TaskName, State

# 看下次采集与队列
python manage.py shell -c "from shared.models import Target,Job; from django.utils import timezone; t=Target.objects.filter(platform='jd').first(); print(timezone.localtime(t.next_due_at), Job.objects.filter(state='pending').count())"

# 临时重启（改完代码后）
Stop-ScheduledTask  -TaskName CompetitorWorker
Start-ScheduledTask -TaskName CompetitorWorker

# 取消关机（改变主意时）
Unregister-ScheduledTask -TaskName CompetitorShutdown -Confirm:$false
# 如果已经在倒计时（60 秒内）
shutdown /a
```

## 三个踩过的坑（都修进任务定义了）

1. **`*>>` 写出来是 UTF-16**：PowerShell 5.1 的重定向默认 Unicode，日志变成「每字符夹空格」，`grep` 完全读不了。
   → 改用 `cmd.exe /c ... >> log 2>&1`（原样字节流）。
2. **Python 的 stderr 被 PowerShell 包装成 `NativeCommandError`**：日志里会掺进一堆 PowerShell 错误格式化文本。
   同样用 cmd 重定向解决。
3. **重定向后 Python 是块缓冲**：日志「憋着」很久才落盘，看日志像卡死了。
   → 启动命令加 `-u`，并 `set PYTHONIOENCODING=utf-8` 保证中文是 UTF-8 而不是 GBK。

## 为什么不用 `docker compose`

也可以（`compose.yaml` 里 web/worker/db 都定义好了），但本机已经在用 Docker 里的 PG 容器，
再起一套 compose 会重复占用 5432/8000。演示阶段用计划任务最省事。
要切 compose 的话：先停这两个任务，再 `docker compose up -d`（改 `DATABASE_URL` 指向 compose 内的 db）。

## 这个方式的边界（诚实说明）

- 触发条件是**用户登录**：机器重启后如果没登录，服务不会自启（可以改成 `-AtStartup` + 指定账号，
  但那样计划任务会以服务身份运行，环境变量与桌面路径都不同，需要单独验证）。
- `runserver` 是开发服务器：单进程、无静态文件优化，只适合本机演示。对外的正式环境用 `compose.yaml` 的 gunicorn。
- 关机任务只执行一次，跑完自动失效；不会每周日重复关机。
