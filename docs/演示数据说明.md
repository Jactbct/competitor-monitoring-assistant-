# 演示数据说明：RTX 5060 监控

## 一句话

系统正在监控一个「影驰 RTX 5060 金属大师」商品，**页面数据是合成的**（不是真实抓取），
但我方商品、定价、毛利底线、流水线、模型归因全是真实运行的。

## 为什么是合成的

本机出口访问 `item.jd.com` 会被 **302 回首页**（连 `robots.txt` 都被跳转），返回内容里
0 处商品信息——这是反爬拦截，不是我们解析的问题。淘宝商品页更要求登录，而本项目
**永不处理登录态**（合规红线）。

所以真实抓取需要：合规网络环境 + 商务/法务确认 + `COLLECTOR_MODE=http`。
在那之前，用结构等价的合成页跑完整流水线：抽取 → 到手价 → diff → LLM 归因 → 建议卡 → 效果回看。

## 数据构成

| 项 | 值 | 说明 |
|---|---|---|
| 监控对象 | `https://item.jd.com/10012345678.html` | JD 商品页格式（`sku-name`/`p-price`/`spec-img`/`choose-attrs`） |
| 竞品 | 影驰 GeForce RTX 5060 金属大师 8G GDDR7 | 店铺：影驰京东自营旗舰店 |
| 我方商品 | `GPU-5060-OURS` RTX 5060 金属大师 8G（在售） | 售价 2599 / 成本 1999 / 毛利底线 0.22 |
| 采集频率 | 120 分钟 | core 优先级（P0 实时、4 小时内处理） |
| 租户账号 | `gpu@demo.local` / `demo12345` | 独立租户「极光数码」，与服饰演示租户隔离 |

三天演进（回填到 10-20 / 10-21 / 10-22）：

| 日期 | 挂牌价 | 促销 | 到手价 | 发生了什么 |
|---|---|---|---|---|
| 10-20 | 2499 | 平台券满2000减100 | **2399** | 基线 |
| 10-21 | 2499 | + 店铺券满1500减80 | **2319** | 促销力度变化（挂牌价没动） |
| 10-22 | 2399 | 平台券 + 店铺券 | **2219** | 真实调价 |

对应两条 P0 建议（均由 LLM 归因，`degraded=false`）：

- 10-21：`2399 → 2319（-3.3%）`，归因「券力度变化」，置信度 0.88
- 10-22：`2319 → 2219（-4.3%）`，归因「真实调价」，置信度 0.88
  动作：「**不要直接跟到 2219**，会让毛利率跌破 22% 底线；单件让利上限约 28.59 元，
  可用小面额券或搭赠替代」

最后这条正是产品的价值点：竞品降了 180 元，但直接跟会亏，系统给的是「不能跟 + 为什么 + 最多让多少」。

## 复现命令

```bash
# 1) 建租户/商品/监控对象（幂等）
python manage.py seed_gpu_demo

# 2) 三天逐个重放（fixture 目录代表不同日期）
for d in day0 day1 day2; do
  python -c "import os,django;os.environ.setdefault('DJANGO_SETTINGS_MODULE','config.settings');django.setup();from django.utils import timezone;from shared.models import Target;Target.objects.filter(platform='jd').update(next_due_at=timezone.now(),circuit_state='closed')"
  COLLECTOR_FIXTURE_DIR=tests/fixtures/jd/$d python manage.py drain_queue --tick
done

# 3) 常驻监控（每 2 小时一轮；默认读 tests/fixtures/pages/10012345678.html，即 10-22 那一版）
python manage.py run_worker --concurrency 2
```

## 换成真实抓取要改什么

1. `.env`：`COLLECTOR_MODE=http`
2. `domain/collect/guardrails.py`：确认域名在 `ALLOWED_HOSTS`（京东已加入，但**加入白名单不等于放行抓取**，
   真实抓取还受 `COLLECTOR_MODE` 控制）
3. 先跑 `python manage.py probe_page --url <真实链接>` 看强结构标记命中数（≥2 才算能解析）
4. 若页面结构与合成页不同，改 `domain/extract/rules.py` 里对应站点的 `SiteProfile`
   （新增站点 = 加一个 profile，不要改 `extract()` 本身）

## 已知限制

- `run_worker` 是前台进程，关掉终端就停；要长期跑用 `docker compose up -d worker`（见 `compose.yaml`）
- 合成页不含 SKU 价格差异（真实京东不同 SKU 价格常不同），这类页面需要额外解析
- 三天的「日期」是回填的，不是真实等待三天；真实运行后新样本会按实际时间累积
