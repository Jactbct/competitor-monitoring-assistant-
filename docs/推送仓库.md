# 推送到 GitHub

> 仓库已在本地建好（3 个提交、tag `v0.3.0`，工作区干净）。只差一个远端地址和一次认证。

## 一、加远端并推送

```bash
cd D:\监控agent

# 1) 加远端（把 <你> 换成 GitHub 用户名；仓库名带空格会被 GitHub 转成连字符）
git remote add origin https://github.com/<你>/competitor-monitoring-assistant.git

# 2) 推送主分支与 tag
git push -u origin main
git push origin --tags

# 3) 用远端 refs 校验（不要只信 push 的退出码）
git ls-remote --tags origin | grep v0.3
```

## 二、认证说明（本机现状）

- `gh` 未安装，`~/.gitconfig` 里凭据助手是 **manager（Git Credential Manager）**，没有存过 GitHub 凭据。
- 第一次 `push` 会弹浏览器登录窗（或要求输入 PAT）。命令行工具是非交互的，**这一步需要你在本机确认**。
- 如果弹窗没出现，用 PAT 推一次（把 token 存到 keychain 由 GCM 管理）：

```bash
git remote set-url origin https://<用户名>@github.com/<用户名>/competitor-monitoring-assistant.git
# 然后在弹出的凭据框里填 PAT（scope 至少 repo）
```

> 注意：不要用 `https://<token>@github.com/...` 的形式写进 remote —— token 会明文留在
> `.git/config` 里，容易在演示/录屏时泄露。

## 三、推完要做的两件小事

1. **确认 `.env` 没被推上去**（里面将来会有你的 API Key）：
   ```bash
   git ls-files | grep -c "^\.env$"     # 期望输出 0
   ```
2. 在仓库设置里补一句 Description，并把 About 的 Website 留空即可（这是内部工具）。

## 四、之后每次发版

```bash
git add -A && git commit -m "feat: ..."
git tag -a v0.3.x -m "v0.3.x ..."
git push origin main --tags
git ls-remote --tags origin | grep v0.3.x   # 远端校验
```

## 五、如果以后要接 CI

仓库里已有 `.github/workflows/ci.yml`（ruff → SQLite 测试 → PG 迁移与授权 → 双后端测试 →
隔离验收 → 判据报告）。推上去之后在 GitHub 的 Actions 页面确认它能跑通，
第一次跑通常会暴露「本地能跑、CI 环境差异」的问题，属正常，按日志调。
