# Agent 能力规格（G2）

> 这份文件回答「这个 Agent 到底做什么、边界在哪」。缺任意一项都不应进入实现。
> 原则：**LLM 是流水线里的函数，不是调度者**。调度权在代码手里。

## 1. 任务边界

**输入**：一个公开商品详情页（URL）+ 该租户对它的优先级 + 我方 SKU（售价/成本/毛利底线）。

**产出**：一条建议卡（8 字段）或一条变化事实卡；都要能回链到具体快照证据。

**一句话**：把「竞品变了」变成「我方该做什么、谁做、什么时候做完、怎么验收」。

**明确不算它的活（拒绝项）**：

| 拒绝 | 表现 |
|---|---|
| 替人做调价决策 | 只给让利额与打平销量，跟不跟由人定（`B_CLASS_ENABLED=0` 时更强） |
| 估算到手价 | 规则算不出就标 `uncertain`，绝不写「大约」 |
| 猜测页面没写的信息 | 促销金额/门槛必须能在原文找到，否则丢弃该条 |
| 登录态取数 | 无 Cookie / 无登录模块 / 无验证码处理 |
| 多步自主查证 | 归因类型是封闭枚举（6 类），不做开放式推理 |

## 2. 工具契约

「工具」= 流水线里的 4 个外部能力。入参/返回/副作用/超时/幂等/失败错误全部写死。

| 工具 | 入参 | 返回 | 副作用 | 超时 | 幂等 | 失败时的可读错误 |
|---|---|---|---|---|---|---|
| 采集 `fetch_page` | url, etag?, last_modified? | `FetchResult(status, body, etag, retry_after_s, crawl_delay_s, not_modified)` | 无（只读公开页） | 12s | 是（304 → 不落快照） | `GuardrailError`（护栏拦截，代码错）；网络异常 → 记失败 + 熔断 |
| 规则抽取 `extract` | html, url | `ExtractResult(fields, strong_hits, promo_items, price)` | 无（纯函数） | — | 是 | 不抛异常；取不到就留空，由异常识别判空壳页 |
| N1 促销抽取（LLM） | page_text, rule_items | `PromoExtraction`（pydantic） | 无 | 30s | 是（缓存 key=内容+prompt+模型） | schema 不合法 → 退规则结果并标 degraded |
| N2 归因+建议（LLM） | 变化事实 + 我方商品 + 证据 | `AnalysisOutput` | 无 | 30s | 是（同上） | 两次不合法 / 证据 ID 无法回链 → 退「只报事实」 |
| 通知 `notify` | suggestion_id | 各渠道结果 | **发外部消息**（企微/邮件） | 8s | 是（唯一键 suggestion+channel+hour） | 企微失败 → 邮件 → 站内，不静默 |

> **当前生产链路里 N1 未接入**（促销由规则引擎抽取，确定性、无需证据校验）。N1 的代码与用例已就绪，
> 但接入需要先把「促销区正文」落到快照里做证据比对，而正文会让快照体积涨 10~50 倍、与 400 天保留冲突。
> 这个取舍记在 [`adr/006-deferred-items.md`](adr/006-deferred-items.md) §4。
> 因此**生产实际生效的是两道门**：schema 校验 + 证据 ID 回链；「证据子串校验」属于 N1，暂未上线。

## 3. 上下文策略

| 项 | 规则 |
|---|---|
| 预算 | 单次调用输入 ≤ 6000 字符（`LLM_MAX_INPUT_CHARS`），单事件 token 上限 6k |
| 送什么 | 只送「变化字段所在区块 + 标题 + 促销区文本」，**不送整页 HTML**（输入从 ~8k 降到 ~1.2k） |
| 不送什么 | 用户信息、其它租户数据、原始 HTML 全文、评价原文 |
| 超预算裁剪顺序 | ① 先砍促销区以外的文本 → ② 砍旧快照证据引文（只留 current）→ ③ 仍超则不进 LLM，走规则路径（确定性降级） |
| 缓存 | `shared.llm_cache`，key = 内容哈希 + prompt 版本 + 模型；同一 URL 被 N 个租户分析时 N1 只算一次 |

## 4. 决策权限

| 动作 | 权限 |
|---|---|
| 采集、抽取、diff、落事件 | **自动**（只读公开页，可回滚，无外部影响） |
| 生成建议卡、写库 | **自动**（草稿态，不通知人） |
| P0 实时推送（企微/邮件） | **自动**，但前置条件：`quality_gate=pass`；价格类在 `B_CLASS_ENABLED=0` 时永远 `manual_required` |
| 采纳建议 → 建任务 | **人工**（admin/operator） |
| 忽略 / 标误报 | **人工**，忽略必须带原因标签 |
| 改价、改标题 | **永不自动**（本期不做写操作） |
| 改采集频率 | **人工改文件 + 重启**，不提供后台旋钮 |

## 5. 失败兜底

| 情况 | 确定性行为 |
|---|---|
| LLM 超时 / 5xx | 指数退避重试 1 次 → 仍失败则用规则归因（`degraded=true`），卡片退化为事实卡 |
| LLM 额度耗尽 | 直接降级不重试（避免账单失控），今日后续事件全部走规则路径 |
| 页面被限流 429 | 读 `Retry-After` → 指数退避 + 熔断；熔断期间不出建议（不用过期数据给建议） |
| 页面结构改版 | 强结构标记 < 2 → 判 `STRUCTURE_CHANGED`：不落快照、不生成事件、目标标异常 + 告警 |
| 检索/数据为空 | 到手价 `uncertain`，结论措辞改成「展示价对比」；成本缺失 → 只出「请补录成本」引导卡 |
| 推送失败 | 企微 → 邮件 → 站内红点；三者都失败写 `notification.status=failed`，不静默丢 |

## 6. 成功判据（可测）

| 指标 | 门槛 | 怎么测 |
|---|---|---|
| 到手价准确率 | ≥ 99%（与人工核算差 ≤0.01） | `tests/eval/test_gate.py` + 每周 20 条抽检 |
| 证据回链率 | 100% | 建议卡里的 `snapshot_evidence_id` 必须能在库中查到（`gate_report` 实测） |
| 证据子串校验 | 100%（N1 上线后） | 目前 N1 未接入，规则引擎本身不产出「自由文本证据」 |
| 幻觉计数 | 0 | 输出金额必须能在原文找到 |
| 建议 8 字段齐全 | 100% | `Card.validate()` 每次落库前执行 |
| 事件→建议时延 | P95 ≤ 90s（P0） | `job.created_at → suggestion.created_at` |
| 降级率 | ≤ 15%（超过必须说明原因） | `MetricDaily.degraded_ratio` |
| 越权成功次数 | 0（>0 立即 P0 告警） | 审计表 + `cross_tenant_blocked` 指标 |
| 采集异常率 | ≤ 2% | `/ops/health` 异常类型分布 |
